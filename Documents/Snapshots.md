# 磁盘快照

本分支提供磁盘快照管理：创建、分页查看、恢复和删除快照。快照包含全部 SCSI 虚拟磁盘、虚拟机配置和来宾状态文件（VMGS）。不保存内存、CPU 运行状态、共享文件夹内容或外部 ISO 文件内容。恢复完成后，虚拟机从关机状态重新启动。

在虚拟机窗口工具栏点击“快照”，输入名称和说明后创建快照。列表每页显示 20 条记录，包含创建时间、父快照和当前分支标记。恢复或删除前需勾选确认框。所有修改操作先请求来宾正常关机，等待 HCS 释放虚拟机，然后修改磁盘链并重新启动；暂停中的虚拟机会先恢复运行。请先保存来宾中的工作。如果来宾在 60 秒内没有正常退出，操作报错，不强制关机。

例如，创建快照 A 后安装软件，再创建快照 B。恢复 A 会回到安装前的磁盘与配置，并创建一条新的可写分支；B 仍保留，可以再次恢复。恢复前当前分支上未保存为快照的改动将被放弃。需要保留这些改动时，先创建一个快照。

快照使用 VHD/VHDX 差分磁盘，创建时无需复制整个虚拟磁盘。原来的磁盘成为冻结的父磁盘，之后的写入进入新的差分磁盘。恢复同样创建新的差分磁盘，避免写入历史快照。物理直通磁盘、重复挂载同一磁盘、没有虚拟磁盘和挂起状态的配置不能创建磁盘快照。

删除快照会移除该恢复点，并重新连接列表中的父子关系；仍被当前分支或其他快照依赖的磁盘必须保留。只有不再被引用、且由快照管理器创建的文件才会回收。删除不会合并或压缩磁盘链，因此删除后的空间释放量取决于依赖关系。连续创建大量快照会增加磁盘链长度，目前没有磁盘合并功能。

快照文件存放在配置文件旁的 `<配置文件名>.snapshots` 目录。不要单独移动、编辑或删除该目录、父磁盘及其中的文件，也不要通过其他虚拟机写入被冻结的磁盘。备份时需要包含配置文件、快照目录以及所有外部父磁盘，并在虚拟机关机时执行。现有 `.7b` 配置格式继续使用 JSON；新增快照元数据使用 UTF-8 无 BOM 的 YAML。

元数据使用专用 YAML 格式：顶层字段逐行保存，值使用 JSON 流式表达式。这些值也是合法的 YAML；管理器只读取自身生成的格式，不支持任意手工重排后的 YAML。

| 文件或字段 | 含义 |
| --- | --- |
| `catalog.yaml` | 快照索引和管理器拥有的文件清单 |
| `version` | 元数据格式版本，目前为 1 |
| `active_snapshot` | 当前工作分支最近恢复或创建的快照 ID；空字符串表示无父快照 |
| `snapshots` | 轻量列表记录，包含 `id`、`parent_id`、`name`、`description`、`created_utc` |
| `disks` | 管理器创建的差分磁盘记录，包含 `path` 和 `parent` |
| `state_files` | 恢复时创建的工作 VMGS/VMRS 文件清单 |
| `garbage` | 待回收的确切文件路径，删除失败时保留供下次重试 |
| `<ID>.yaml` | 单个快照清单，包含 `version`、`id`、`configuration` |
| `configuration` | 该快照的虚拟机配置，磁盘与 VMGS 指向冻结状态，内存保存路径为空 |
| `preparation.yaml` / `paths` | 发布事务前的确切准备文件清单；中断后回滚这些文件 |
| `transaction.yaml` / `catalog` | 已发布事务的目标配置和目标索引；中断后继续完成事务 |
| `store.lock` | 防止同一虚拟机的多个快照管理操作并发修改 |

配置和元数据通过文件刷新及原子替换提交。事务发布前退出，下一次启动清理准备文件；事务发布后退出，下一次启动先完成配置与索引更新，再启动虚拟机。分页查看不会执行事务恢复。错误异步写入程序目录下的 `logs/snapshots.log`。

## 开发验证

使用支持 `.slnx` 的 Visual Studio 2022 或更新版本、C++ UWP 构建组件与 Windows 11 SDK，打开 `NanaBox.slnx` 并构建 NanaBox 项目的 Release x64 配置。项目按功能划分源码目录，XAML 和 IDL 项目引用随文件位置更新。命令行构建可以直接指定 `NanaBox/NanaBox.vcxproj`，避免解决方案及打包项目同时编译同一项目。本地已使用 Visual Studio 2026 的 v145 工具链完成 Release x64 构建。

完成一次 Release x64 构建以生成 C++/WinRT 头文件后，以管理员权限执行：

```text
python -X utf8 'Tools/test_snapshots.py'
```

测试直接调用 Windows 虚拟磁盘提供程序创建 VHD 和 VHDX，写入原始扇区并核对恢复结果，覆盖多磁盘、配置、VMGS、分支、删除、准备阶段回滚、事务恢复、分页和无效输入。这组测试已通过，并接入 GitHub Actions。测试使用模拟的 VMGS 内容，因此该测试不能代替真实来宾的启动和关机验证；当前尚未进行真实来宾的端到端验证。测试产物位于 `__tmp`，已有测试目录时拒绝覆盖。
